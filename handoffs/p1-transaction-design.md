# P1 SessionRunEvent transactional design

Baseline commit: `c002f8c4efe475c89c9f14d3995d44e6a5df5b27`
State: independently reviewed; mode-gated degradation and empty-manifest invariants corrected. P1 implementation remains blocked until P0 closure.

## Shared contract

- Extend `ReplayRecorder` semantics through one authoritative SQLite/WAL ledger; do not add a recorder or an independent JSONL writer. `hermes_eval::RunRecord` remains benchmark-only and gateway `RunRecord` remains live in-memory status.
- The ledger is the only committed source of truth. JSONL is a derived, optional compatibility export; `HERMES_REPLAY_ENABLED` may toggle export generation only, never ledger writes, migration state, or replay verification.
- Keep exactly six semantic run outcomes: `success`, `failure`, `timeout`, `cancellation`, `blocked`, and `dead_lettered`. Closed typed `TerminalReason` values carry causes. Effect reconciliation states such as `unknown_non_resumable` are not seventh run outcomes.
- Every canonical object named below is RFC 8785/JCS-v1: `canonicalization_algorithm = "rfc8785-jcs"` and `canonicalization_version = 1`. Hashes are full SHA-256; shortened hashes are display-only.
- No network effect occurs inside a ledger transaction.

## R1 — protected artifact sealing precedes ledger references

**Invariant.** SQL event rows, manifests, outbox payloads, and append reservations contain only explicit allowlisted public projection/identity plus a `SealedArtifactRef` digest; private replay bytes never enter SQLite or an outbox row. `VersionedRedactor::redact` is fallible, records its version, and may reject an append. `AppendSemanticIdentity` contains canonical allowlisted `public_identity_jcs` and a persisted `private_fingerprint` only: `HMAC-SHA-256(K_ledger_identity, "hermes.session-run.append-private-fingerprint/v1" || length(public_identity_jcs) || public_identity_jcs || length(credential_free_private_jcs) || credential_free_private_jcs)`. The distinct ledger-identity key is never an artifact-encryption key; persist its fingerprint algorithm/version/key ID and the keyed fingerprint, never private JCS bytes or a raw private digest. The identity excludes allocator-created event ID/sequence/timestamp, encryption nonce, ciphertext/digest, storage path, and `SealedArtifactRef`. The reservation fixes its event ID/timestamp once; final commit allocates sequence. Exact replay is true only while its sealed artifact is durable and read-verified.

**Boundary.** `derive_append_identity` redacts into canonical public identity and credential-free private JCS in memory, resolves the versioned ledger-identity key, and computes its domain-separated keyed fingerprint before `reserve_append` (R3); it writes no private bytes, raw private digest, or artifact reference. Only the winning reservation lease invokes `prepare_artifact`: JCS-v1 private replay bytes → authenticated envelope encryption → durable temporary CAS write → file `fsync` → recomputed SHA-256/digest check → atomic rename → parent-directory `fsync`. `publish_sealed_ref` may CAS that already-verified digest into the reservation; only `commit_reserved_append` may put it in an event, manifest, or outbox row.

**Failure behavior.** A redaction rejection or unavailable/unknown/revoked ledger-identity key returns typed `AppendIdentityKeyUnavailable` before reservation or sealing; it never falls back to unkeyed/public-only comparison or `sanitized_no_seal`. A write, `fsync`, digest mismatch, rename, or directory-`fsync` failure fails the lease without an event/outbox reference. When an artifact-sealing key/store is unavailable after successful identity fingerprinting, the original append is never committed without the manifest required by its `EffectIntent`. Only a successfully resolved `manual` mode may return typed `DegradedManualAppend` and atomically append a distinct public-only `ManualAppendDegradedAudit` event, with its own derived append key, no `EffectIntent`, an explicitly policy-derived empty manifest, `redaction_state = sanitized_no_seal`, and `exact_replay = false`; it persists no private bytes and authorizes no effect. `reviewed`, `autonomous_local`, `ci`, and `remote_worker` fail before event/outbox commit when sealing is unavailable. A crash before sealed-reference publication may leave only a GC-able orphan; after publication, an equivalent retry verifies and reuses that reference rather than resealing.

**Post-commit lifecycle.** `read_exact_artifact(ref, authorization)` requires authorization, then verifies CAS digest, retention state, non-revoked key ID, AEAD authentication, plaintext JCS-v1 digest, schema, and redactor version before exposing private bytes. An unauthorized request returns typed `ExactReplayUnauthorized` without changing artifact state. Missing, corrupt, key-revoked, or deleted material returns typed `ExactReplayUnavailable`; `mark_artifact_unavailable` atomically records `unavailable_{missing,corrupt,key_revoked,retention_deleted}`, sets affected runs `exact_replay = false`, and appends an empty-manifest audit event. It never substitutes a public projection as exact replay. `retire_artifact` first atomically marks a no-exact-replay retirement/tombstone and audit, then destroys/revokes key material or unlinks the object with directory `fsync`, and finally records retirement; shared CAS content is deleted only after all live references are retired. Recovery completes a retiring tombstone rather than restoring an exact claim.

**Gate.** Inject failure at redaction, identity-key resolution/HMAC, encryption, write, each `fsync`, digest check, rename, publication, and final commit; assert no committed event/outbox reference lacks a verified sealed object, no private sentinel is queryable, and a pre-publication orphan is the sole permitted crash residue. Query every SQLite ledger/reservation/outbox/artifact column for a unique credential-free private sentinel and its raw SHA-256 digest; both must be absent while the versioned keyed fingerprint is present. Concurrent equivalent appenders must produce one reservation/seal/receipt. Mutate, remove, revoke, expire, and retire a committed artifact, including each retirement crash boundary; prove read-time verification, durable unavailable audit/state, no public fallback, and no false `exact_replay`.

## R2 — one-way atomic migration and cutover

**Invariant.** `LedgerConnectionFactory` is the only way to open `sessions.db` for ledger work, migrations, export reads, and workers. It sets and verifies WAL before migration and applies `synchronous=FULL`, `foreign_keys=ON`, and bounded `busy_timeout` on every connection; raw or differently configured ledger connections are prohibited.

**Boundary.** `migrate_and_cut_over_v0_to_v1` uses that factory and one `BEGIN IMMEDIATE` transaction for all v1 tables, indexes, validation, `state_meta.run_ledger_schema_version = 1`, and persisted `state_meta.ledger_primary = 1`. The factory validates both markers before every ledger use. Unknown/newer versions, missing/mismatched markers, or failed validation reject startup before any writer runs.

**Failure behavior.** A crash exposes either the prior v0 schema/markers or a fully validated v1 ledger-primary schema, never partial DDL or a dual writer. Downgrade is an explicit offline, verified backup/export and restore procedure; no environment variable, rollout flag, or runtime option can re-enable a legacy writer. Existing 16-character JSONL chains remain labeled v0 (or carry a raw-file digest) and are never silently rehashed as JCS-v1 provenance.

**Gate.** Inject a crash after every migration DDL, validation, marker write, and before commit; reopen through the factory and prove all-or-nothing visibility, PRAGMA enforcement, marker agreement, refusal of unknown/mismatched versions, no legacy writer, and explicit v0/raw-digest treatment.

## R3 — ledger-derived required manifest and append idempotency

**Invariant.** `AppendEvent` contains a stable `append_key` and typed `EffectIntent` values, never caller-supplied destinations or a caller-supplied manifest. Equality compares canonical public identity plus the versioned domain-separated ledger-keyed private fingerprint, never a private JCS value/raw digest or a newly randomized sealed reference. A closed, versioned `DispatchPolicyV1` inside the ledger derives every required destination, stable downstream idempotency key, redacted payload projection, sealed-artifact digest, and order.

**Boundary.** `reserve_append(identity)` is the first `BEGIN IMMEDIATE`: it atomically returns the existing committed receipt only when append key, public identity, fingerprint version/key ID, and keyed private fingerprint match; it rejects changed public identity as `AppendKeyConflict` and same-key/same-public/different-private-fingerprint as `AppendKeyConflict::PrivateFingerprintMismatch`; otherwise it grants one generation/tokenized `session_run_append_reservations` lease with a frozen event ID/timestamp. Matching contenders wait/read that lease and do not seal. After R1 publishes a verified reference (or `sanitized_no_seal`), `commit_reserved_append(lease)` verifies the lease CAS, allocates contiguous sequence/head, derives and JCS-v1 canonicalizes the manifest, persists its immutable canonical bytes/digest, inserts the event and exactly the derived outbox set, advances the chain/run header, marks the receipt committed, and commits.

**Failure behavior.** An unavailable/unknown ledger-identity key fails before reservation, sealing, or manual degradation. An expired reservation can be reclaimed only by the same public identity/fingerprint tuple and retains its frozen event allocation; a published reference is verified and reused, while an unpublished lease may be safely resealed by its new owner. A stale reservation token cannot commit. A retry after commit returns the original receipt; any changed public identity or private fingerprint is rejected before sealing. Manifest derivation, hashing, insert, or validation failure leaves no event/outbox rows. Empty manifests are permitted only where the closed policy explicitly derives none, such as internal delivery-result, artifact-state audit, and non-resumable-intent events.

**Gate.** Pause many identical requests before reservation, after reservation, after seal publication, and after commit; prove one semantic reservation, one live/published sealed object, one receipt/event/effect key, and no concurrency conflict or duplicate orphan. Retry one append key with equal public identity but different credential-free private JCS and prove `PrivateFingerprintMismatch` before sealing; repeat with unavailable identity key and prove fail-closed. SQL-scan every ledger table for private sentinel/raw private SHA-256 absence. Attempt empty/partial caller manifests, conflicting-key retries, stale reservation commit, lease-expiry takeover, and forced manifest/outbox mismatch; prove partial dispatch cannot commit and conflicts fail closed before sealing.

## R4 — fenced claims and durable downstream idempotency

**Invariant.** At-least-once outbox delivery is safe only at a durable idempotency boundary. Every registered `OutboxDestinationHandler` accepts the stable event idempotency key and proves a durable downstream dedupe receipt; one without that guarantee cannot register. `NonResumableEffectExecutor` is not an outbox destination/handler and is governed only by R9's separate one-shot path.

**Boundary.** `claim_next` is one transaction that selects a ready or expired row, increments the attempt count and lease generation, assigns a fresh unguessable lease token and expiry, and records the claim. `ack`, `nack`, and `complete_delivery` compare-and-swap row ID plus token, not owner identity. The dispatcher passes the key to the registered handler, receives/persists its durable receipt, then invokes completion; it cannot claim a non-resumable intent.

**Failure behavior.** An old or reused owner cannot complete a reclaimed claim. A crash after the side effect but before completion can re-deliver only through the downstream dedupe boundary. Missing destinations, invalid payloads, and decode failures receive closed typed errors, consume counted attempts, and deterministically reach `dead_lettered` at the configured limit rather than disappearing. Registration or routing of a non-dedupe handler through the outbox fails closed.

**Gate.** Simulate concurrent claims, expired reclaim, stale-token ACK/NACK, handler death after an effect, duplicate delivery, missing route, invalid decode, attempt exhaustion, and attempted non-dedupe registration/routing; prove one downstream receipt, monotonic attempts/generations, deterministic typed dead-lettering, and no non-resumable `claim_next`.

## R5 — delivery completion atomically updates event, outbox, and run

**Invariant.** A terminal outbox row, its delivery-result event, persisted receipt/error, and run outcome never diverge. `session_runs` serializes `RunExit`, candidate outcome, required-delivery resolution, and an irreversible required-dead-letter latch; intermediate delivery states are not new semantic outcomes.

**Boundary.** `complete_delivery(row_id, lease_token, result)` uses one SQLite transaction to CAS the token, persist receipt/error, append immutable `DeliveryResult`, transition the row, lock the run header, and call `reconcile_run_finalization`. `finalize_run_exit` locks that same header in its own transaction before appending `RunExit` and calls the same reconciler. The reconciler finalizes the candidate immediately when its exit is recorded and zero required rows exist or all required rows are already ACKed; otherwise it records pending delivery. Required exhaustion atomically latches/finalizes `dead_lettered`, even before `RunExit`; `DispatchPolicyV1` derives an empty manifest for internal completion/audit events.

**Failure behavior.** An ACK before an exit records delivery-resolved state and the later finalizer commits the candidate outcome. An early required dead-letter finalizes/latches `dead_lettered`; the later `RunExit` is still appended but cannot overwrite it. Concurrent ACK, exhaustion, and exit transactions serialize on the run header, so neither zero-row runs nor already-resolved runs strand in pending state.

**Gate.** Race `RunExit` with last ACK and required exhaustion, including delivery completion before exit; prove exactly one exit event, candidate finalization for zero/all-ACK rows, irreversible early-dead-letter precedence, and no terminal row without its result event/receipt/error or a pending strand after restart.

## R6 — one finalizer and stale-run recovery

**Invariant.** Every `AgentLoop::run` and `run_stream` invocation has exactly one run header/start event and exactly one recorded `RunExit`; exactly one serialized finalization decision governs the six-outcome run state.

**Boundary.** Outer `run` and `run_stream` wrappers call `create_run_and_start` atomically, execute inner functions that return a closed `RunExit`, and call `finalize_run_exit` before returning. The finalizer exhaustively maps each `TerminalReason` to one of the six outcomes, appends the terminal execution event under R5's run-header lock, persists the candidate, and invokes its reconciler. Each open run has an owner lease and heartbeat. Startup reconciliation resumes only safely resumable work or atomically terminalizes stale work as `failure` with `process_death`.

**Failure behavior.** A pre-existing required-dead-letter latch cannot be overwritten by a normal `RunExit`; a zero-required or already-ACKed run finalizes in the finalizer transaction. Ledger-finalizer failure overrides a normal inner result in every fail-closed mode. A non-resumable unknown effect cannot be resumed and is terminalized as `failure` with its typed reason. New runs never silently strand old open runs.

**Gate.** Instrument normal, graceful early return, error, interrupt, timeout, cost guard, tool-loop guard, cancellation, and streaming exits; each must produce one start and one exit record. Race these exits with last ACK/dead-letter, then kill a leased process, expire its heartbeat, and restart to prove safe resume or typed `failure/process_death`, never an indefinitely open or pending-stranded run.

## R7 — real typed alpha dispatch

**Invariant.** P1 chooses real alpha execution. `/mission enqueue` appends a typed `EffectIntent::Alpha` and required `Destination::AlphaRuntimeV1` row; neither `/mission replay` nor `loop_queue` may report replay success merely by changing status.

**Boundary.** The closed `DispatchPolicyV1` derives the alpha row. An exhaustive `AlphaRouter` claims it through R4, passes its stable idempotency key to a named registered production handler, and invokes R5 only with that handler's durable receipt. `/mission replay` claims/replays durable ledger intent; no `loop_queue.jsonl` writer or status-only reader participates in production execution.

**Failure behavior.** Missing/invalid alpha variants NACK with a closed typed reason and eventually dead-letter; they cannot yield “replay complete.” Restart resumes through the outbox and durable dedupe boundary.

**Gate.** Exercise `/mission enqueue` and `/mission replay` through a production handler, kill between claim/effect/completion, and verify exactly one downstream receipt after recovery. Exercise a missing and invalid variant and verify typed dead-lettering, no status-only success, and the resulting run outcome.

## R8 — full run-scoped exports and one JCS verifier

**Invariant.** An export is a complete, immutable, per-`run_id` view, not a session-wide concatenation or bounded tail. Every accepted replay/proof reader uses one shared JCS-v1 verifier.

**Boundary.** `export_run(run_id)` reads one consistent ledger snapshot and atomically replaces only that run's full export after file `fsync`, rename, and directory `fsync`. The envelope includes all immutable events, canonical manifests, sealed-artifact references, compatibility aliases, source watermark, total event count, complete range, and `complete = true`. Session lookup requires an explicit `latest` or `all` run selector. `replay_trace_control::{verify_replay_log, verify_replay_export}`, `systems::summarize_replay_log`, `command_reasoning_session::replay::replay_trace_integrity`, `swarm_specpatch_studio::handle_studio_command`, and `doctor_routes::replay_integrity_summaries` call the shared verifier before accepting data.

**Failure behavior.** A crash before export replacement leaves the prior complete per-run export or no export, never a partial accepted file. Missing/false `complete`, truncated range/count, stale watermark, absent manifest, non-JCS-v1 data, or any chain/hash mismatch is rejected for replay, summaries, integrity, and UI claims. Exact replay additionally requires R1's verified artifact reader; unavailable private material is a typed rejection, never a public-projection substitute. A bounded tail is never a valid export or verifier input.

**Gate.** Export multi-run sessions, crash at write/`fsync`/rename/directory-`fsync`, truncate/tamper every required field, and route each named consumer through the verifier; prove latest/all selection, full completeness metadata, rejection of tails, and no ledger behavior change when `HERMES_REPLAY_ENABLED` changes.

## R9 — commit effect intent before every effect

**Invariant.** Each effect-capable hook, tool, model operation, or callback has a durable typed intent before invocation. Resumable intents have an R3-derived required outbox row and use R4; no direct call may execute first and be recorded afterward as reconciled. A non-dedupe effect is either blocked or uses the explicitly separate, policy-allowlisted `NonResumableEffectExecutor`, never an outbox handler.

**Boundary.** For resumable work, the runtime appends the intent/outbox before an inline or background dispatcher claims and executes it, and results close only through R5. For an allowed non-resumable effect, `record_nonresumable_intent` commits an empty-manifest intent and `armed` effect state before `claim_once` CASes it to `executing` with a one-shot token. That executor is neither registered nor claimable by R4, has no lease-expiry retry, and uses `complete_once` to append its result and invoke R5's run-header reconciler. Recovery of any `executing` one-shot marks `EffectReconciliation::UnknownNonResumable` in one transaction and finalizes `failure/effect_non_resumable_unknown`; it never runs the effect again.

**Failure behavior.** A pre-intent crash cannot have invoked an effect. A post-intent crash leaves a recoverable durable intent only for a dedupe-capable destination. A one-shot crash or uncertain response is explicit operator-visible unknown/non-resumable, never retried or presented as reconciled success; a blocked non-dedupe operation has no effect.

**Gate.** Crash-inject before intent commit, after resumable commit/before claim, after a dedupe-capable effect/before R5, and after one-shot claim/effect/response. Assert respectively no effect, one deduped receipt after recovery, and explicit unknown/non-resumable failure with no automatic replay. Attempt to route a one-shot through the outbox and to retry an `executing` one-shot; both must fail.

## R10 — typed ExecutionMode is P1-A's first gate

**Invariant.** Before any ledger integration, P1-A defines closed `ExecutionMode` variants `manual`, `reviewed`, `autonomous_local`, `ci`, and `remote_worker`, plus one deterministic `resolve_execution_mode(defaults, profile, config, environment, cli)` resolver with recorded source precedence. Objective labels such as `autonomous` are not modes.

**Boundary.** Ledger entrypoints accept only `ResolvedExecutionMode`, never free-form strings or environment reads. The resolver's precedence is built-in defaults, profile, config file, environment, then CLI; P1-C may extend the typed configuration surface but must reuse this resolver.

**Failure behavior.** With no override at any layer, resolution returns the typed built-in default and records that source. An explicitly present but empty, unknown, contradictory, or otherwise invalid value at any layer fails closed rather than falling through to a lower-precedence value. Redaction, identity-key, ledger-append, and finalizer failures are hard errors in every mode. Only after redaction/identity succeed, and only when the artifact-sealing key or CAS store is unavailable while the ledger can commit the audit, may a successfully resolved `manual` mode return typed `DegradedManualAppend`; it rejects the original append and may commit only the distinct public-only `ManualAppendDegradedAudit` defined by R1, whose closed policy derives no effect intent and an empty manifest. `reviewed`, `autonomous_local`, `ci`, and `remote_worker` treat sealing failures as fatal and commit no degraded state.

**Gate.** Run an exhaustive precedence/conflict matrix before the first ledger call, including no overrides → recorded built-in default and explicitly present empty/unknown/contradictory values → fail closed without lower-layer fallback. Cross every resolved mode with redaction rejection, identity-key unavailable, sealing-key unavailable, CAS-store unavailable, ledger-append failure, and finalizer failure. Redaction/identity/ledger/finalizer failures are hard errors with no committed degraded state in every mode. For sealing-key/CAS unavailability only, `manual` may return typed `DegradedManualAppend`; the original append remains absent and the sole optional committed row is one distinct idempotent `ManualAppendDegradedAudit` with no effect intent and a policy-derived empty manifest. Every automatic mode fails without degraded state. Prove no objective label or environment-only fallback can silently downgrade a mandatory run.

## Focused implementation gates

P1 may begin only after P0 closure and only when all R1–R10 gates above are represented by focused failure/crash tests. The minimum proof set additionally verifies the full mode × redaction/identity/sealing/CAS/ledger/finalizer outcome matrix, including manual-only sealing/CAS degradation and universal hard failure for redaction/identity/ledger/finalizer faults; contiguous concurrent sequences; immutable-chain tamper rejection; credentials absent from projections and exports; full legacy JSONL compatibility aliases; and a real alpha side effect rather than a diagnostic/status transition.
